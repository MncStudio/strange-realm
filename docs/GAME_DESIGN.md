# 诡境 · 当前游戏设计

设计依据：先读 `CORE_DESIGN_PRINCIPLES.md`，再读 `REFACTOR_PLAN.md`。本文记录当前可运行实现；旧职业版本保存在 `archive/GAME_DESIGN_LEGACY.md`，不能再作为新功能验收依据。

## 核心体验

4～6位现实朋友始终坐在一起，电脑主持恐怖故事，手机处理私人信息和每幕2～3个选择。开局全部为普通访客，不分配赌徒、电工、狼人或其他职业/阵营。立场变化由过程中发生的事件和玩家选择产生。

手机回答“发生了什么”“现在做什么”。不展示背包、技能树或四条资源面板。线索和以前的私人结果放在可折叠的“我已经知道的情况”。

## 阶段

大厅准备 → 普通人开场 → 事件演出 → 主持开放讨论与秘密选择 → 全员选择自动结算 → 公共后果演出＋本人结果 → 全员点已读 → 下一事件/最终揭晓。

讨论和选择不限时，选择时仍可交流。演出可以跳过，不影响裁决。主持不能跳过在线玩家的选择或已读。已读在后果演出结束后开放；最后一人已读自动推进一次。最后一幕也先看结果，再揭晓秘密。

每阶段有递增stageId，刷新恢复该阶段的已提交和已读；旧阶段消息无效。断线保留180秒重连凭证；游戏中角色状态继续占位。主持可明确替离线者选择本事件默认行为或确认已读；默认行为仍可能违反指令，断线本身不感染。

## 第七位访客

共同目标：查明登记异常、解除循环门禁、验证出口边界，让人类离开而不把第七位访客带出去。前两项通过登记调查、回应房门或查维修线路取得；第三项通过镜面/回声查证，或终幕至少两人共同查验取得。

7幕、12个条件事件。第2幕根据是否查明登记出现不同房门；第3幕与第6幕根据是否回应房门呈现不同后续；第4幕有合法的水盆变体；第5幕依据门禁状态查镜面或提供替代补救。有限随机只发生在同级合法候选之间。

完整内容来自 `packages/scenarios/seventh-visitor/scenario.json`，节点、合法转移和选择见 `SCENARIO_EVENTS.md`。JSON保存文案、指令模板、条件、选项和演出，必要的因果规则由本剧本的rules.ts确定执行。

## 私人指令

每人每幕至多1条，人数上限为总人数的一半向下取整。不是人人每幕都有。根据登记、接触和帮助的历史分配，条件相同时使用固定种子随机。

- 门认得你：至少另一人回应房门，自己不能回应。
- 别把它叫出来：不能有人回应。仅对具有签名历史、且与前一个接收者不同的人开放；不是每局强制互斥。
- 把它的话接下去：回应模仿自己的广播，仅在对应声音事件和已有接触历史时出现。
- 它不想你洗掉名字：本轮护持另一人而非净化自己。仅对曾帮助过别人且未收到过此指令的人出现，避免反复封死同一人的净化机会。

实际行动满足条件则服从，否则拒绝并产生一次异常原因。系统不判断现实中是否坦白、被人发现或说服了谁。坦白不会自动消除风险，所有选择仍可提交。

## 感染、护持与净化

服务端真实阶段为0正常、1潜伏、2觉醒、3异变。初始全部0，没有预先放置的感染者。异常接触、违抗私人指令或主动传播才产生进阶原因；同人同幕最多增加一阶，不随时间增加。

潜伏阶段不通过网络发送给本人。手机只收到征兆；正常人查冷水也可能出现同类征兆。觉醒和异变时才明确告知已知变化。异变不强制加入敌方，仍能查证、护持、抵抗和请求净化。

护持消耗自己的本轮行动，每次护持提供1次接触抵挡；多次接触可耗尽抵挡。它同时满足异变者的净化帮助条件，不抵消违抗指令。

主动传播只在允许接触的事件中，由已经获知异变身份的人显式选择对象，替换一个非默认情境选项，仍保持最多3个选项。不能当轮刚异变就获得传播行动；抵抗和护持可以阻止传播。未知潜伏状态不改变菜单。

4～5人局共有2次净化机会，6人局3次。仅在水盆/最后净化事件中申请，不建立背包。正常至觉醒阶段使用一次后回到正常；异变者需要自己申请＋别人同幕护持，使用一次降至潜伏。之后可以再净化。机会不足不扣成负数，未轮到者不消耗；不足时仍可抵抗和帮助别人。

净化以本幕开始状态处理，再处理本幕新增感染，不能净化尚未发生的接触。多人同时申请按种子的稳定顺序分配，网络到达顺序不决定优势。

## 结算顺序与结局

冻结选择 → 护持/抵抗 → 净化既有异常 → 情境行动/主动传播 → 私人指令 → 合并异常原因并转换阶段 → 终局 → 生成公开和本人结果。

第7幕提供：查验后离开、直接离开、留下控制异常。

- 至少两人查验，且登记和门禁已查明，可以补足边界事实。
- 三项逃生依据齐全时，直接离开者通过边界；查验离开者须自身正常才通过。判定不在之前泄露别人的真实状态。
- 至少半数人留守可以封闭旅馆。
- 有感染者通过则“异常被带出”；全员正常通过则“正常逃脱”；其余留守足够则“封闭旅馆”；否则“困于旅馆”，有部分正常者已通过时使用对应的部分逃脱叙事。

中途不永久淘汰。所有人参与到终幕，终局按是否离开、真实状态、护持/抵抗/传播行为逐人解释，不用旧职业任务判胜，也不强制每局出现个人输家。

## 演出与可访问性

三张本地环境图继续使用。公共演出由JSON cue驱动，包含文字、短音效、停顿和单次黑屏。声音用本地Web Audio合成，需主持点击启用，可调音量/静音；浏览器禁止声音时显示字幕并继续。不是已配音的完整电影。

演出不改变世界状态；公共电脑负责公共声音，手机首版用清晰的私人指令卡提示。尊重减少动态设置，可关闭动效；黑屏不闪烁。按房间、stageId和cueId记录已演出内容，刷新不重播整幕；服务端保存是否完成。

## 验证记录与剩余工作

本次重构已通过新规则单测、类型检查、真实六人Colyseus的异常携出/全员正常退房两条路线，以及四个模拟手机页面的七幕流程、全员已读、刷新与重开。当前67项单测通过（引擎/剧本37项、输入边界30项），类型检查、构建和六人协议检查通过。四人和六人单窗口均完成手动选择、全员已读、七幕、结局、重开和刷新恢复；模拟手机额外验证声音被禁止时回退字幕、主动启用声音和音量限制。旧64项测试被新玩法测试替换，不构成新规则证据。

仍需组织4人和6人各一场面对面实玩，检查讨论是否自然、私人指令是否有说服力、恐怖演出是否有效，以及是否存在长期无事可做。这是体验验收，不能用自动玩家替代。完整录音配音、更多场景素材、跨设备凭证恢复及持久化存档尚未实现。

本次修复：自动同伴从护持改为无目标选择时必须清除旧目标参数，避免服务端正确拒绝后试玩等待。已用20个种子的实际引擎提交添加回归测试；另以20种混合选择验证七幕内结束。通用二人一幕合成剧本无需职业、感染或旅馆数值。

构建产物另行启动验证：生产静态页面可读取，编译后的服务端HTTP健康检查、剧本API及真实WebSocket房间创建/同步通过。验收占用的独立进程已清理。

真人验收操作与记录模板见PLAYTEST.md。终局公共屏可保存只包含已揭晓信息的故事JSON，不是存档或确定性重演文件。当前需重点验证签名的收益不足、传播的自利动机和熟悉规则后固定安全路线的问题。
