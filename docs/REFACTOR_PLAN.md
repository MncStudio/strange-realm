# 诡境：核心设计审查与项目重构执行计划

状态：需求审查与执行计划；代码重构及自动化验收已推进，真人体验验收未完成。当前实现见GAME_DESIGN.md和SCENARIO_EVENTS.md。

依据：`CORE_DESIGN_PRINCIPLES.md` 为本次目标；`GAME_DESIGN.md`、`ARCHITECTURE.md` 和现有源代码为旧实现证据。原则文档保留原文，本文件补充落地规则、差异和验收。

## 1. 对需求的理解与优先级

4～6位现实朋友坐在一起；电脑主持恐怖故事，手机提供私人信息与少量秘密选择。所有人普通人开局，没有预置敌对者。玩家行为及私人怪谈指令造成有因果的感染和异变，故事随真实结果变化。

已确认：发现异变后仍可抵抗或与异常合作，由玩家选择。已确认的推进方式继续适用：全员提交自动结算，每人确认结果已读，全员已读自动推进；没有讨论或行动倒计时。

本次目标替代旧的固定六职业、开局私人任务、资源条经营和大量背包操作。此前提出的赌徒/电工互斥目标、押注、稀缺物品交易和最终供电拉票计划不进入本次重构。

保留 Vue / TypeScript / Pinia / Router / Vite、Node / Colyseus、pnpm workspace、JSON剧本、局域网扫码、服务端权威与本人权限隔离。不增加数据库、AI裁决、地图或虚拟移动。先做《第七位访客》，通过最小合成剧本验证扩展能力，不制作第二个商业内容剧本。

## 2. 原则文档的重要缺陷与补充决策

| 缺口 | 不补充会发生什么 | 本次建议的落地规则 |
| --- | --- | --- |
| 私人指令缺少服从动机与拒绝代价 | 玩家全部坦白或统一拒绝，冲突消失 | 指令给出本轮可验证条件、风险征兆和拒绝的代价类别；服从可能保护自己但让其他人承担风险。拒绝始终可选。 |
| 有的指令依赖现实语言 | “不要被发现”“说服别人”无法由程序裁决 | 秘密只是玩家自行管理的叙事。判定只使用实际行动、对象、事件和历史；不检测说谎、截图、口头坦白或现实说服归因。 |
| 坦白后的冲突没有定义 | 公布私人消息即可找到全员无成本的答案 | 设计需要分担代价的事件，以及有意互斥的私人要求。诚实能帮助讨论，但不会增加净化机会或消除接触异常的后果。 |
| 感染只有阶段名称 | 进阶、传染、抵抗、净化及同时行动都可能任意处理 | 采用下述确定性阶段、知识边界和结算顺序；任何变化记录原因，玩家在重大变化前得到可理解的征兆。 |
| 潜伏期“不知道”缺少权限设计 | 即使界面隐藏，私人WebSocket或按钮差异仍会暴露感染 | 服务端保存真实状态和玩家已知信息两套模型。潜伏期不发送真实阶段、数值、传染者或由真实状态独有的按钮。 |
| 异变后的能动性与胜负不清 | 变怪物等于被强制当狼人，或者此后无事可做 | 不强制换阵营。每轮仍有抵抗/协助的选择；传播行为由本人选择。结局评价逃生、真实状态与行为，不以服从指令次数判胜。 |
| “动态故事”没有取舍规则 | 随机抽卡遮盖因果，关键事件迟迟不来，或剧情互相矛盾 | 使用有条件的事件图、叙事节拍和强制终局兜底；先匹配玩家行为的后续事件，再对同级合法变体做有限随机。 |
| 恐怖优先没有演出协议 | 只有图片与长文字；有人未看完便跳转，刷新重播惊吓 | 演出与规则分开。服务端确认阶段，主持播放固定cue序列；演出就绪后开放讨论/选择，结果播放完成且全员已读才推进。 |
| 死亡、离场和断线未定义 | 某人失去参与，或者一台手机使全局永久卡住 | 第一版不在中途永久淘汰；异变者仍提交有意义的选择。离线代选和代确认必须由主持明确操作，只能处理离线者。 |
| 没有可玩性验收 | 自动化通过只证明能运行，无法证明朋友愿意讨论 | 增加坦白策略、抵抗策略、零感染/多人感染分支与真人聚会验收；不能用机器人跑通替代体验验证。 |

这份原则文档适合作为设计边界，补上上述规则和完整事件后，才能作为实现规格。下述数值是第一版验证用默认值，不代表已经经过真人平衡测试。

## 3. 玩法规格默认值

### 3.1 每轮与节奏

流程：事件演出 → 自由讨论及私人指令 → 手机秘密选择 → 统一裁决及后果演出 → 全员已读 → 下一事件或终局。

讨论与行动期间始终允许现实交流。主持在演出后点击“开始讨论与选择”，避免用倒计时决定大家是否看懂；每位玩家提交后即锁定，不再额外设置集体准备按钮。最后一人提交自动裁决，演出不影响裁决结果。结果已读按钮在公共后果演出结束后开放。最后一轮同样先展示后果，全员已读后才揭晓秘密。

每局最多7个事件回合；第7轮必须按状态完成终局，不承诺固定分钟数。手机每个行动阶段显示2～3个情境选项、至多1条当前私人指令和本轮私人结果；已有线索可折叠查看，不设置职业、任务树、背包经营或四条资源HUD。大屏以当前困境、公共后果和必要的可读进展为主。

阶段使用唯一、单调增加的 `stageId`。重复已读幂等；旧阶段的行动或已读被拒绝；同阶段的重连保留选择和确认。所有在线玩家都须提交/已读。主持可明确替离线者选择本事件的保守默认行为、确认已读。默认行为同样接受怪谈判定，不承诺无代价；离线本身不构成感染原因。

### 3.2 私人指令

每名玩家最多1条生效指令。每轮新指令接收者上限为人数的一半向下取整；旧指令未结束的人不再叠加。优先根据曾经接触的异常、受过的帮助、已知线索和真实行为选择接收者；只有同等条件时使用有种子随机。

一条指令需配置：触发条件、接收者条件、有效回合、实际行动判定、服从后果、拒绝后果、本人文案、公开后果以及终局回放原因。第一版指令均在本轮结束时判定，跨轮影响通过历史事实和后续事件实现。

不把“所有人收到不同目标”作为开局要求，也不保证每轮所有人都收到消息。没有指令的人仍能通过公开困境的不同选择、保护别人、查证和抵抗影响故事。

### 3.3 感染与选择

首局原型使用0正常、1潜伏、2觉醒、3异变四个内部阶段。所有人初始0。满足配置中的接触异常、违反指令或传播条件才增加；每人每轮最多增加一个阶段，不随时间自动增加。重复原因不会重复叠加，但所有触发原因进入审计记录。

潜伏者收到征兆，不能收到真实阶段。觉醒/异变时才明确告知自身变化及可采取的行动。正常者也可能因有因果的寒冷、停电或惊吓事件出现相似征兆，不能把“收到征兆”做成百分之百感染检测。

传播不是被动光环。第一版仅在具有明确接触选项的事件中开放“让异常接触另一人”，必须选择实际对象、受事件条件限制，每名异变者每轮至多一次；不会根据现实坐位、聊天或共同已读传播。单靠别人被感染，不算任何人的自动胜利。

净化机会为局内有限公共事实：4～5人局2次，6人局3次；仅在配置的净化事件中使用，文案直接说明剩余机会，不建立物品背包。0～2阶段净化后回到正常；异变者须本人选择净化并有同伴同轮护持，消耗一次机会降至潜伏，之后还可再净化。无人护持时可压制自身异常，仍能拒绝传播并帮助同伴，不锁死为敌方。机会不足时允许无法彻底恢复，但必须保留抵抗及救人行为。

净化不能在同一轮立刻消除刚发生的感染：以回合开始状态为依据，先净化原有感染、再处理本轮新增感染。避免刚被传染者获得未显示的额外行动，或循环传染/净化。同一轮多名申请者使用有种子的稳定次序分配有限机会；行动前明确说明可能不足，未获得机会不消耗机会。

### 3.4 统一裁决与终局

固定顺序：冻结本轮全部选择 → 保护/抵抗 → 查证/净化 → 情境行动及主动传播 → 指令判定 → 事件余波 → 状态转换 → 终局检查 → 生成演出与各投影。新异变的能力只能下轮使用；WebSocket到达顺序不影响结果。

公共目标为阻止第七位访客离开旅馆，并让人类通过边界。逃生以“确认登记异常、解除门禁循环、验证出口边界”三个叙事事实判断，不把原电力/封印/出口四条资源模型继续套用。

终局至少包括：正常逃脱、异常被带出、封闭旅馆阻止外溢、困于旅馆。无感染局也能结束，不能为了出现怪物强行随机感染。个人结算展示是否离开、真实异变状态、抵抗或传播过什么、对同伴造成哪些帮助/后果；不强制每局存在个人输家。

第7轮仍无法打开安全边界则进入封闭或被困结局，按是否成功控制异常判断；已满足逃生条件时提供最后的“共同查验后离开／直接离开／留下控制异常”情境选择，并按实际组合与真实状态确定结局。留下与离开均不能在手机提前暴露其他人的真实状态。

## 4. 一轮事件必须写到这个完整度

示例“门后的第七声敲击”，仅为本次原创原型规格：

- 前提：仍被困，尚未取得门后的门禁线索；本局最多出现一次。
- 大屏：门内有人说知道出口，当前困境是是否回应；说明回应可能帮助逃生，也可能让异常接触回应者。
- 每个人均有三个选项：回应门内声音、检查敲击规律、为一名同伴护持。拒绝开门通过选择后两项实现。
- 指令A：一名先前听过门内声音的人收到“本轮至少另一人回应，而你不能回应”；拒绝会出现新的感染征兆。
- 指令B：若存在符合不同历史条件的另一接收者，可收到“本轮不能有人回应”；其条件与A有意互斥。4人局也不超过两名新接收者。
- 实际效果：有人回应则取得门禁线索，回应者承受异常接触；护持先抵挡一次对应接触。检查者获得可靠的条件线索。每名未满足自己指令的人产生一次感染原因，仍受单轮进阶上限约束。
- 讨论意义：即使两人坦白，群体仍要决定是否推进线索、谁承担接触风险、是否花一人的行动护持，以及谁愿意违抗自己的指令。系统不判断谁“说服”了谁。
- 公开结果：门是否回应、线索是否取得、现场出现的征兆；不公布回应者的秘密选择和指令接收者。
- 私人结果：本人的选择效果、指令是否满足、本人获知的征兆；潜伏期仍不透露原始感染阶段。
- 后续：有人回应则允许“旅馆模仿你们的声音”等因果后续；全部拒绝则进入其他查证路线。拒绝不能令全局永远停滞，失去的机会或拖延必须影响最终结果。
- 回放：揭示每个选择、护持、互斥指令和感染实际变化，把“为什么变成这样”串成因果链。

完整剧本需按此模板写出至少12个事件节点及合法转移，覆盖7回合的多条完整路径，不能只有故事标题或随机文案。

- [Betrayal at House on the Hill 第三版官方介绍与规则入口](https://instructions.hasbro.com/en-au/instruction/avalon-hill-betrayal-at-house-on-the-hill-3rd-edition-cooperative-board-game-for-ages-12-and-up-for-3-6-players)：从共同探索过渡到背叛与恐怖事件。借鉴事件推动关系变化，不照搬地图、职业属性或必有叛徒。

### 7.1 接口和内容模型

- 公共投影：当前阶段和stageId、公共困境、公开玩家提交/已读状态、公共演出cue、已知剧情事实。删除原始角色、感染、私人指令及其他玩家行动的任何字段。
- 本人投影：已获知的征兆/身份、当前私人指令、当前2～3个实际选项、本人的提交和结果。真实状态即使属于本人，也必须经过“本人已知”投影。
- 行动和已读携带stageId；身份来自已认证连接。演出完成仅接受主持连接上报，不能据客户端cue判胜或修改世界状态。
- 引擎管理阶段、确定性随机、行动冻结和效果审计；剧本管理事件资格、指令判定、感染条件和结局。通过服务端内容接口连接，不把“旅馆”写进通用房间或页面。
- 剧本JSON保存事件、选项、指令、演出cue、触发与后果；可用白名单的条件/效果表达式及必要TS规则模块。禁止任意字符串执行，不建设复杂可视化编辑器或完整脚本语言。
- 演出每段以stageId和cueId去重；只由公共电脑播放公共声音。进入房间时主持点击一次启用声音，私人信息首版使用手机明确提示，手机音效只在设备允许且本人启用时播放。声音、动画或图片失败不改变规则、不使游戏卡住。
- 规则先完成裁决，再产生cue和投影，绝不以音效播放成功、手机振动或动画结束作为恐怖效果判定依据。

### 7.2 测试范围

- 权限：拦截全部公共和私人网络消息，验证隐藏阶段、感染原因、指令、他人选择确实未发送；还检查选项/禁用提示不会意外泄露潜伏状态。
- 因果：每种进阶、传播、抵抗和净化都有来源；同轮多原因只进一阶；新异变者不能当轮连锁传播；净化不能清除同轮刚发生的感染。
- 指令：最多一条生效，上限随人数变化；拒绝不被禁止；有意互斥要求不会令行动界面失去合法选择；坦白本身不触发系统处罚。
- 故事：合法条件、优先级、无重复关键事件、无路径死锁、条件筛选后有限随机、第7轮终局兜底；零感染与多人感染均可结束。
- 阶段：全员提交自动裁决，全员已读自动推进一次，旧stageId拒绝；断线代操作仅处理离线者；刷新恢复当前演出和状态。
- 演出：声音被浏览器拦截、素材缺失、静音和减少动态都能走完；不能因重复加载重播整个事件或提前进入选择。
- 产品：4/5/6人选择都有意义，机器人只证明流程；真人每轮能复述当前困境，发生至少一次对有代价选择的讨论；有人异常后仍能抵抗、求助或合作，没有长期旁观者。
