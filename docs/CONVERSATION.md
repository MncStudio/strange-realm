# 交谈版玩法与验收

2026-10-19。用户明确接受“先好玩、减少阅读与登记，让玩家发现矛盾”的修改方案，并要求执行。以下流程为本次实现；人物之间新增的亲历、具体文案和20～30分钟预算属于实现时的创作选择，未经真人试玩确认。

## 新局流程

一分钟左右的共同开场 → 手机读身份、每人介绍一件亲历 → 公屏揭第一批发现、自由追问 → 新材料到场、再讨论 → 独立写一个凶手昵称 → 四票或三票交齐揭开 → 公屏录入、揭晓。

新模式使用`screen-led`与`flowVersion: 2`。内部阶段仍沿用`opening/dossier/search1/search2/vote/ended`标识，不另设必须完成的对质阶段。没有倒计时，不因人数或角色分配限制调查机会。

- 删除逐人选地点、调查次数、已发言/放弃登记、完成计数。
- 删除关键判断选择题，包括页面、打印票、投票请求和服务端裁决。正确多数只看凶手；理由当面说，不自动评分。
- 公共材料按剧情批次发放，无需找齐地点。每批直接展示本批正文，前批材料仍可展开回看。
- 物证不再附带“可以问什么”和推理结论。需要时可主动请求全桌提示，或对少量已公开原物请求核验。
- 手机默认只有身份、一个目的、三条本人亲历；完整亲历与开口方向折叠。不逐阶段自动讲解，不按每份公共证据追加教学提示。
- 规则集中在开局；物证真实性、杀人边界等必要公平条件保留。

公共故事、公共物证和完整结局只在公共屏。手机里的亲历仍是人物自己知道的经历，不是另发公共故事；只有本人的角色凭证可以读取。

## 三份剧本的调整

### 闭馆之后

开场175字左右。第一批给出错误表面时间、工具署名和旧卷宗，容易先怀疑修复师；角色间有编号页、签字和归档的交叉亲历，可以先互相追问。第二批提供两份原片、同一通急呼与设备校验记录，玩家自己对齐时间，不再直接写出“两人覆盖窗口，所以只剩经纪人”。可选核验解释时间换算，但无需调用才能取得解题条件。

### 末班渡口

开场159字左右。检验员知道经理曾拦下报告，调度员知道魏岸要求采访原件，记者持有经理签名的材料；这些提供谈话入口，不设置必须保住的第二个秘密。第一批保留工作目录、旧账与合照，第二批给出实际班次及三份人像；不替玩家算出每个人的最早到达/最晚离开，不显示“只剩经理”的答案选项。

### 人鱼·暗渠来信

开场156字左右。**用户已经明确说目标电视剧不是《人鱼》；本案仅保留为此前误选题材的同人草稿，不能宣称完成了用户指定剧集的改编。** 此次只随通用交谈流程一并调整，正确剧集仍待用户提供。

学生知道申诉与经办人，救人者知道剪刀与掌伤，退休民警听过死者提到申诉；桌上应先出现解释与质疑。第二批将衣物材质、格纹、裂口、补线逐件列出，移除直接指认式结论。逐边拼合结果需主动核验才展示。M05依旧提供本次搏斗来源这一公平事实，不要求现实法医知识。

## 设计推演，非真人结果

以下是可行的讨论路径，不是强制台词或实测行为：

1. 钟馆第一轮可能从修复师工具牌怀疑起，经修复师与档案员谈签字、编号形成新疑问；原片到场后再纠正时间与嫌疑。凶手可谈别人参与的旧事，但不能否认已核验原片。
2. 渡口第一轮可能怀疑掌握载台的调度员；询问采访与维护款后，第二轮把人像放回实际行程。车辆日志没有乘客姓名，因此需要组合，而非读出单条“凶手是谁”。
3. 暗渠第一轮可能怀疑戏服署名者或借剪刀者；本人解释与第二轮原件区分剪切、搏斗和拼合，最后才把动机接上。

三条路径都允许改判，有足够公开材料兜底，不因玩家不愿承认旧事而无法解题。但公开材料仍足以供一名熟练玩家独立求解；这次没有靠强迫保密或额外胜利任务阻止他。私人亲历与节奏能否带动全桌，需要真人验证。

## 版本、权限和保存

- 新建房间复制剧本的流程版本；无字段旧房间按v1处理。旧公屏局保留登记、对质及原裁决，旧六人局保持原流程。
- 三份`story.v1.json`保存修改前的完整内容。服务端按房间版本选择当前稿或原稿；中止/结束后重开才选择当前稿和v2。
- `screen_verify`仅公共屏可用，只能核对讨论中已公开的材料。未请求的核验结论不发给客户端，也不传给手机。
- `screen_votes`仍校验全体人数、玩家唯一性、合法嫌疑人和纸票已揭开；全部通过才一次写入。v2忽略并丢弃客户端额外提交的判断或证词字段。
- 已揭材料、主动核验、角色和版本持久化。纸票录入草稿继续按房间与阶段存于公共屏会话存储。

## 验收边界

自动化检查分别覆盖规则、接口、恢复、页面与版本兼容，不能计为真人玩法结果。真人验收只优先观察：每人有没有主动问别人；有没有人因新信息改变怀疑；揭晓时能否说出此前忽略的一条信息。

本次实际程序验证：101项规则/HTTP/SSE测试通过，包含三份v2内容、私卡与未来核验隔离、只投嫌疑人、多数/分票、纸票原子校验、原版存档原文与机制保留、重开切版以及核验重启恢复。

浏览器实际验证：三份公屏故事分别跑完三/四部隔离手机整局与单窗口试玩；六人原整局与试玩回归通过。检查了无登记按钮、无选择题、按批发证、提示与核验主动触发、票据打印样式、录入草稿刷新、导出和重开。320/390px手机及1280px公屏无横向溢出，脚本错误为零。已查看钟馆公共开场、390px私卡及1280px讨论截图；输出在各故事`test-results/<id>/conversation/`。

不把20～30分钟预算当测量，不把测试完成称为“已经好玩”。本次未做面对面聚会、实体纸票或真实Wi-Fi手机扫码测试。
