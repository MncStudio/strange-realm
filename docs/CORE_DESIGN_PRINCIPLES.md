这次我们把之前确定的想法全部收敛，形成一份可以长期使用的《诡境》核心设计原则。它既是游戏策划的基础，也是以后让 Codex 开发、修改和扩展剧本时必须遵守的标准。

STRANGE REALM · GAME DESIGN V1.0

# 《诡境》核心设计原则

一款由电脑主持、面向现实朋友聚会的多人互动恐怖故事游戏。

玩家共同面对恐怖事件，却可能因私人指令、个人选择和身份异变，逐渐产生猜疑、欺骗、合作与背叛。

核心体验：恐怖氛围优先 · 面对面互动 · 动态故事 · 极简操作 · 可重复游玩

## 一、不可改变的10条核心原则

### 1. 恐怖体验是第一优先级

电脑大屏是游戏的中心，负责营造恐怖氛围。

通过画面、声音、广播、停顿、灯光变化和突发事件，让所有玩家共同感到紧张。

游戏的重点不是操作，而是让玩家沉浸在正在发生的恐怖故事里。

### 2. 所有玩家现实中始终坐在一起

游戏采用一台公共电脑大屏 + 多台玩家手机的形式。

- 电脑负责主持、公共剧情与结算演出。
- 手机负责私人信息、怪谈指令和个人行动。
- 玩家通过面对面交流完成讨论、说服、欺骗和合作。

不需要地图、虚拟移动、房间布局或复杂角色控制。

### 3. 所有人以普通人身份开局

游戏开始时，所有玩家都是普通人。

不提前分配狼人、怪物或敌对阵营。

玩家的身份和立场可能根据游戏过程中发生的事件与个人选择发生改变。

### 4. 游戏始终存在明确的共同目标

例如：在天亮之前逃离诡异旅馆。

所有玩家都知道最终需要完成什么。

当前事件也必须让玩家明白需要处理的问题。

不能让玩家不知道自己为什么参与讨论，也不知道下一步要做什么。

### 5. 采用固定且简单的阶段循环

阶段一：事件发生

电脑大屏演出恐怖事件，提出当前困境。

阶段二：自由讨论

大家面对面交流。系统可以向部分玩家下达私人怪谈指令。

阶段三：秘密行动

每个人通过手机提交行动，可以遵守集体约定，也可以秘密违背。

行动期间仍允许交流。

阶段四：统一结算

电脑根据所有人的行动及历史状态计算结果，通过大屏演出公共后果，并向相关玩家发送私人结果。

每轮重复这一过程，直到触发结局。

### 6. 私人怪谈指令是核心冲突来源

系统可以根据故事进展与玩家行为，向特定玩家发送只有本人能看到的行动准则。

例如：

> 你认识这扇门。
>
> 不要让任何人发现这一点。
>
> 必须让至少一个人打开它，但你自己不能参与。

玩家可以服从，也可以违抗。

违抗需要承担可追溯的后果，而不是禁止选择。

私人指令并非每个人、每一轮都必须获得，避免信息和任务堆积。

### 7. 感染与身份异变由游戏过程产生

玩家违反怪谈指令、触发异常事件，或受到其他玩家影响后，可能逐渐被感染。

感染具有不同阶段：

正常人类

潜伏感染

异常觉醒

怪物异变

潜伏期玩家可能只感受到异常征兆，并不知道自己已经感染。

异变后可能获得秘密传播感染的能力。

感染不应随意发生，必须符合事件或行为条件。玩家可以调查、抵抗或尝试净化，但这些行为需要承担合理的成本。

### 8. 玩家自由交流，不能强制保密

游戏允许玩家自由说话。

可以坦白收到的私人指令，也可以隐藏、撒谎或误导别人。

不需要 AI 监听现实中的对话，也不需要判断玩家说的是真话还是假话。

秘密是否被公开，由玩家自行决定；游戏只负责记录实际行动和结果。

坦白可以帮助团队，但不应该自动消除风险。

### 9. 故事必须根据玩家选择动态变化

剧本不是固定顺序播放的电影，也不是简单的分支选择题。

下一段故事由以下因素共同决定：

- 当前公共事件
- 所有玩家的实际行动
- 已触发的怪谈规则
- 玩家感染及身份状态
- 此前发生过的关键事件
- 满足条件时的有限随机变化

同一个剧本反复游玩，可以产生不同事件、不同人际关系、不同感染过程和不同结局。

随机制造未知，玩家选择决定故事走向。

### 10. 极简操作，始终让玩家知道自己在做什么

这是所有功能设计的最高约束之一。

### 每一个阶段，界面只需要回答两个问题：

## 发生了什么？

## 现在我要干什么？

手机不应出现大量复杂按钮、菜单、数值、道具和操作系统。

每个行动阶段，只呈现少量与当前困境直接相关的选择。

玩家大部分时间应该看大屏、听声音、与朋友讨论，而不是低头研究手机界面。

## 二、游戏必须具备的完整闭环

| 环节   | 目标                 |
| ---- | ------------------ |
| 加入游戏 | 手机扫码，进入同一场恐怖故事     |
| 故事开始 | 所有人以人类身份面对共同困境     |
| 恐怖事件 | 大屏制造紧张氛围和当前问题      |
| 私人指令 | 部分玩家出现与集体利益冲突的行动准则 |
| 玩家行动 | 每个人秘密做出选择          |
| 后果演出 | 玩家行动影响局势，可能产生感染    |
| 故事变化 | 根据历史行为触发新的恐怖事件     |
| 最终结局 | 根据逃生情况和玩家真实状态结算    |
| 结局揭晓 | 回顾关键选择、感染传播和秘密行为   |
| 再次游玩 | 同一剧本出现不同过程与结局      |

## 三、明确禁止的过度设计

以下内容不应成为第一版的开发重点：

- 地图探索、房间布局、角色自由移动
- 固定狼人阵营和复杂职业
- 技能树、装备系统、复杂数值面板
- 大量交易、背包、任务菜单
- 玩家必须记忆的大量规则
- 需要一直盯着手机的交互
- 没有因果依据的随机感染与身份变化
- 每局固定播放同样的剧情
- 为了增加玩法而加入与恐怖体验无关的功能

不是未来永远不能加入这些内容，而是除非它能明显增强核心体验，否则不应该开发。

## 四、多剧本扩展原则

《诡境》是游戏平台，而《第七位访客》只是其中一个剧本。

每个剧本以 JSON 为主，定义事件、私人指令、行动及后果、画面音效、触发条件和结局。

所有剧本共用：

房间系统 + 公共大屏 + 私人手机 + 阶段流程 + 事件判断 + 行动结算。

不同剧本可以拥有不同恐怖主题和特殊机制，但不得破坏平台的简单交互原则。

## 五、判断游戏是否设计成功的标准

不是有多少个剧本、多少种怪物、多少个按钮，而是能不能让六个朋友玩出这样的体验：

> “我明明记得大家说好不打开那扇门！”
>
> “我没开啊！”
>
> “可是刚才电脑为什么显示门打开了？”
>
> “等等，你手机刚才是不是收到什么了？”
>
> “我真的不知道为什么会这样……”
>
> 大屏突然熄灭。
>
> 一个人的手机响起。
>
> “你已经把它带进来了。”

这才是我们想要的《诡境》。

建议将这份规范保存为项目中的 `docs/CORE_DESIGN_PRINCIPLES.md`。

以后每次给 Codex 增加功能或添加剧本，都要求先读取这个文件，并检查是否符合核心设计原则。

我们的最终目标不是做一款复杂的多人游戏，而是让一群坐在一起的朋友，真正经历一场由自己选择推动、每次都可能不同的恐怖故事。
