# 诡境 · StrangeRealm

朋友围坐，电脑展示公共案情，手机保管各自的私人身份。

首页可选四部独立故事：

| 故事 | 人数 | 场景 | 目标时长（未经真人计时） |
| --- | --- | --- | --- |
| 雪夜来信 | 6人 | 暴雪旅馆、广播与十年前旧案 | 45～60分钟 |
| 闭馆之后 | 3人 | 旧钟馆、未校时的记录与旧交接单 | 20～30分钟 |
| 末班渡口 | 4人 | 暴雨渡口、跨岸行程与即时位置记录 | 20～30分钟 |
| 人鱼·暗渠来信 | 4人 | 《人鱼》背景下的独立同人案、暗渠救援与两块碎布 | 20～30分钟 |

三人《闭馆之后》与四人《末班渡口》《人鱼·暗渠来信》：简短共同开场 → 私人身份与互相介绍 → 两批发现与自由追问 → 只投凶手 → 公共屏揭晓。每人只有查凶或避免被识破一个目的，不逐人登记调查或发言。

《人鱼·暗渠来信》是此前误选题材后保留的同人草稿：用户已明确目标剧集不是《人鱼》，正确剧名仍待补充。本案命案与结局独立创作，不代表电视剧原剧情。创作来源与作者说明见[同人剧本说明](docs/MERMAID_LETTER.md)（含剧透）。

六人《雪夜来信》保持原玩法：读角色 → 开场 → 手机两轮搜证与讨论 → 对质补查 → 手机秘密指认 → 真相复盘。没有倒计时。

人物直接使用入席昵称：例如昵称“小明”分到修复师，卷宗、线索和复盘都会称他为“小明”，同时保留修复师身份。故事中的NPC姓名保持固定。

## 最简单的启动方式（Mac）

安装 **Node.js 22 或更新版本**后，双击项目中的 **`启动游戏.command`**。

第一次会安装依赖并打开浏览器。保持终端窗口开着，电脑不要休眠。结束时在终端按 `Ctrl+C`。

也可以在项目目录运行：

```sh
pnpm install
pnpm dev
```

或者使用 npm：

```sh
npm install
npm start
```

电脑首页：**http://localhost:3210**。`npm start`会自动打开浏览器；`pnpm dev`只启动服务。

如果端口占用，可以使用 `PORT=3211 pnpm dev`。不要直接双击HTML文件；多人同步需要本地服务运行。

## 和朋友玩

1. 电脑打开首页，选择三人、四人或六人的故事，点击“创建公共屏”。
2. 对应人数的玩家用手机与电脑连接同一Wi-Fi，扫描公共屏二维码，填写昵称入席。公共屏不占席位，电脑操作者也可以用手机参加。
3. 公共屏操作者也是普通玩家，用自己的手机加入；不需要增加一位主持人。

### 三人《闭馆之后》、四人《末班渡口》《人鱼·暗渠来信》

1. 公共屏用约一分钟讲清命案和人物关系，再发手机私人身份。
2. 手机默认只有一个目的、三条本人亲历；完整亲历与开口方向可展开。每人介绍自己，听到与自己有关的事就追问，不用点击“已发言”。
3. 公共屏按剧情揭示两批材料，玩家自由讨论。没有逐人搜证次数、地点选择或完成打卡。
4. 不默认展示解题提示。卡住时再请求提示；少量原物可主动核对，核验不是推进的必选操作。
5. 讨论后，各自用纸只写“本人昵称、凶手昵称”，折好交齐并同时揭开。公共屏可打印对应人数空票，操作者一次录入全部选择；不提供答案选择题。
6. 多数指对凶手即正确指认；四人需三票，三人需两票。分票不硬判输赢。理由在桌上说，程序不评分。
7. 完整故事与结果只在公共屏，手机继续保留自己的卡。

新流程适用于2026-10-19后的新局或重开局。运行中的旧局沿用原版材料和操作，不会突然切换。具体设计、交谈推演与验证边界见[交谈版说明](docs/CONVERSATION.md)。

### 六人《雪夜来信》

公共屏开始后，每人先读手机档案，再共同看开场。每轮在手机查一处，完成讨论后全员确认；对质可补查。各自用手机提交嫌疑人、关键判断和证词选择，收齐后揭晓。

《闭馆之后》必须三人入席，《末班渡口》《人鱼·暗渠来信》必须四人入席，《雪夜来信》必须六人入席，不支持直接少人开始。真相固定，已知答案的玩家不适合再作为未知真相玩家重玩。重开会随机重新分配角色，案件本身不变。

### 手机连不上

- 手机要打开电脑的局域网地址，例如 `http://192.168.1.20:3210`，手机上的`localhost`指向手机自己。
- 公共屏的地址下拉框可选择不同网卡。优先选Wi-Fi所在网段，避免VPN、虚拟网卡和`169.254`地址。
- 确认手机与电脑处于同一局域网，路由器未启用访客隔离；macOS首次询问时允许Node接收入站连接。
- 二维码和邀请地址不含角色或主持凭证，其他玩家扫码只能加入自己的席位。
- 手机推荐在Safari或Chrome中打开，同一个席位持续使用同一个地址和浏览器。应用内浏览器可能使用不同存储空间。

## 自己检查完整流程

首页点击 **“一个人试完整流程”**，确认剧透提醒。

- 一个窗口，左侧公共屏、右侧个人手机。
- 顶部下拉框按所选故事切换三名、四名或六名角色，分别查看私人内容。
- 三人和四人版从左侧公共屏推进、登记调查和录入模拟纸票；右侧只查看角色卡与方向。
- 六人版在右侧完成自己的操作，再点“其余5人完成本阶段”；投票时助手用同一份选择完成其余未投席位。
- 试玩房只能在服务器本机创建，不允许真实玩家加入。

**试玩会看到所有人的秘密与凶手。正式参与本案前请勿试玩。** 试玩助手为每个席位使用正常玩家凭证，不绕过正式游戏的权限和阶段校验。

## 刷新、掉线与保存

- 连接实时同步采用HTTP + SSE；刷新、短暂断网后会凭本机浏览器保存的凭证回到原席位。
- 服务每次有效操作后把房间保存到`data/rooms.json`，重启后可恢复阶段、角色、线索和选票。首页有最近使用的公共屏、席位和试玩入口。
- 旧三人局保持原手机玩法与阶段顺序；中止或结束后重开，才切换为新的公共屏模式。纸票录入草稿保存在公共屏浏览器的会话存储中，刷新可继续，全部核对提交后才写入房间存档。
- 不同步真实谈话，不记录麦克风，不发送到外部服务。
- 浏览器清除存储或换设备后，不能自动认领旧席位。大厅可由公共屏移除旧席位重新加入；游戏开始后请使用原浏览器，或明确中止本局。
- 某人提前离开时不自动代选、不判凶手获胜。暂停交流或由公共屏明确中止，再返回大厅。
- 无连接且48小时没有操作的房间会清理。`data`是本机存档，不应分享或提交到Git；其中有全部游戏状态及身份凭证。

docs/GAME.md                   玩法设计、完整真相与验收记录
docs/AFTER_CLOSING.md           三人案设计、证据链与验证记录（含剧透）
docs/LAST_FERRY.md              四人案设计、证据链与验证记录（含剧透）

## 添加下一部故事

1. 为新故事新建英文目录，例如`stories/last-train`，仅复制当前三人或四人剧本的`story.json`；不要复制用于旧存档的`story.v1.json`。
2. 编辑其中的`story.json`，给故事设置唯一`id`，填写标题、开场、角色、地点、两轮物证、判断选项、答案、提示和复盘。
3. 每个角色使用唯一`id`，角色数与`players`相同；每个地点每轮恰有一份物证。复盘中的证据编号必须存在。
   正文提及玩家人物时写`{{role:角色id}}`，例如`{{role:broker}}进入展厅`；服务端会填入本局对应昵称。角色定义的`name`仍可保留作者原名，NPC直接写固定名字。
4. 运行`pnpm test`，再重启服务。首页会读取新的故事目录，无需新增HTML。

默认故事模式为`classic`。采用三人版同类公共屏主持流程时，配置`playMode: "screen-led"`，并填写`briefing`、`screenNotes`、每个角色的`actionCard`、物证`screenHints`和`screenReplay`；加载时会校验。

当前公屏新局采用“介绍→两批发现与自由交谈→只投凶手”，六人保留原来的两轮搜证与对质玩法，支持故事配置的人数为3～8；**这不代表《雪夜来信》已有三四五人版**。三人选择《闭馆之后》，四人选择《末班渡口》或《人鱼·暗渠来信》。新故事若要拍卖、交易、第三轮搜证或多名凶手，需扩展通用规则，不能只改故事文案。

私密JSON不从网页提供下载。不要把答案、完整角色或原始故事配置复制进HTML。所有网页文案按纯文本输出。

## 检查方法

```sh
pnpm check
```

检查语法，并运行规则与真实HTTP/SSE测试，覆盖昵称代入、私卡隔离、分批发证、核验权限、仅嫌疑人选票、纸票原子录入、多数与分票、旧局原文兼容与服务重启恢复。

浏览器完整流程检查：

```sh
pnpm exec playwright install chromium
pnpm test:browser
```

会启动独立的临时测试服务，分别用三个、四个、六个相互隔离的手机浏览器跑完整局，并检查故事选择、单窗口试玩、刷新、复盘下载及重开。结果截图按故事ID分放在`test-results/`下，不写入正式存档。只检查四人本可运行`node test/browser.mjs last-ferry`或`node test/browser.mjs mermaid-letter`，三人本使用`after-closing`。
